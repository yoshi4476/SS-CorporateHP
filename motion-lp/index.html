Core principles

Five, no more

Modular Architecture

Scroll, split, progress, cursor — each capability is an isolated ES module. Import what you use; the rest never ships.

Attribute-Based Integration

Behaviour lives in your markup as data-anim-* attributes. No configuration objects, no imperative choreography.

Effortless Initialization

One import, one call. Elements are discovered, split, observed and driven automatically — including content added later.

Wide Range of Effects

Fades, char reveals, scroll-bound progress, pinned panels, magnetic hovers — composed from one small, coherent core.

Performance Oriented

Transform and opacity only. One rAF loop for the whole page. Reads are batched; layout is never invalidated mid-frame.

Under the hood

Four decisions

Native scroll, preserved

Inertia is an interpolation layer on top of real scrolling — the scrollbar, anchors, and accessibility tools keep working. Smoothing is a single tuned lerp factor, 0.09.

Modular by design

Every capability is an ES module with one export. import { ProgressSystem } costs you progress — nothing else rides along.

Markup-driven configuration

Attributes are the API: data-anim-fade, data-anim-split, data-anim-progress, data-anim-sticky. Per-element tuning via custom properties like --d.

No layout shift

Only transform and opacity are ever animated. Pinning is emulated with translates, so the document flow — and your CLS score — never move.
